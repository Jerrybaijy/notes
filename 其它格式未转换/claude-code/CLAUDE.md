# 全局约定

适用于**所有项目**。项目特有的约定放在各项目自己的 `CLAUDE.md` 或
`~/.claude/projects/<项目路径>/memory/` 里，不要往这里堆。

## 改代码前必须拿到明确授权

修改代码前必须先拿到用户明确说出「开始执行」四个字。以下都不算授权：

- 用户描述需求或提出问题（例如「还需要一个 xxx 字段」「把 A 改成 B」）
- 用户回答 AskUserQuestion 的选项
- 用户说「好的」「可以」「嗯」「收到」
- 你自己判断需求清晰、变更很小、觉得「顺手改一下」

只读操作（查代码、读文件、跑只读查询、git status/diff/log/show）不需要授权。

**提问不受限制**，该问的细节照常问清。限制的是「开始执行」之前不许自己拍板改代码，
不许把问出来的结论当作授权，也不许用「先改一点点试试」绕过。

节奏：调研 → 提问把细节问清 → 给方案 → 说明「等你下令『开始执行』我再动手」→ 停住。

- 方案和清单可以先写好，但不调用 Edit / Write 改仓库里的文件
- 已处于等命令状态时不再追问细节或改方案，干等，直到用户主动发新消息
- 拿到「开始执行」后一次性做完并验证，然后汇报
- 新建文件、建迁移、改配置同样属于写操作；只读排查不受限

## git 写操作全部由用户自己执行

不要执行任何 git 写操作：commit、push、pull、merge、rebase、cherry-pick、reset、stash、
checkout 切分支、创建分支、tag。

改动完成后只口头提示「建议 commit」并列出改动内容，不调用 git 写命令，也不代拟 commit 信息。
git status / log / diff 等只读命令可用。

## Markdown 文档标题不加序号

标题一律用纯文字（`## 概述`，不是 `## 1. 概述`）。需要体现顺序时用 `##`/`###` 层级本身，
或在正文里用有序列表表达。

## 行文规范

适用于对话回复和写出来的文档。

- **语气与句式**：用书面语，不用口语填充词和感叹号；句子写成完整陈述，祈使句只在给操作步骤时用；不用破折号插话补充信息，需要补充就另起一句或拆成两句；不用「其实」「说白了」「基本上」这类过渡词开场。
- **结论先行**：先给结论再给依据；判断要带依据，说明快在哪、有多大风险；没把握的事说「待确认」。
- **信息密度**：能用表格或列表就不用长段落；不重复用户已知的信息，不逐条复述刚做过的动作；删掉不影响理解的修饰语和客套话。
- **格式**：强调用加粗，只标真正需要扫读的部分，一段不超过两处；代码、命令、路径、字段名一律用反引号；标题层级不超过三级。

## 操作浏览器优先借用用户标签页

用 bsk 操作网页时：

- 先 `bsk tab list --scope user` 查用户窗口有没有现成标签页；有就 `tab borrow` 借用，干完 `tab return` 归还，别在 Agent Window 里重开同一个网页。
- 没有就在 Agent Window 新开（`navigate` / `tab create`）。
- 动手前先只读确认：`get-html` / `snapshot` / `screenshot` 对用户标签页直接可用，不用借。
- 一次对话只开一个 session，中途不停，最后统一 `bsk session stop`。
